# 676：load 后的异步筛选界面

当前网络 PR 的原合同真实验收为 2/3：339、595 通过，676 失败。676 的 Orders 导航成功，但第 2 个动作立即查询 Filters 控件时元素尚未构建。

只读浏览器对照使用同一 Orders 页面，不重放业务动作。Chrome 在 2933 ms 触发 load、Moli 当前网络二进制在 2766 ms 触发 load，两者此时 Filters 数量均为 0。随后模板和数据 XHR 均以 200 完成，最终 Filters 数量均为 2；两者记录的请求均无失败或持续 pending。该失败不能归因为 Moli 独有的提前 load。

原 main@de109 的 676 已完成全部五个动作及筛选 GET 200，仅在 Referer 网络评分项失败。因此本次是更早的异步界面就绪前提缺失，不能把两个层次的失败混为一谈。

既有测试框架支持独立的动作前 readiness 声明，原任务 465 已使用同一机制。676 的补充就绪前提将在独立合同中验证；原动作、评分和失败记录保持。DOMContentLoaded 也不保证这种后续异步 UI 已完成。
